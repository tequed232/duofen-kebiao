# 极致 Liquid Glass 版（测试分支）

> **这是一条测试分支，不是主项目的发布分支。**
> 上游主项目：[tequed232/duofen-kebiao](https://github.com/tequed232/duofen-kebiao)（`main`）。
> 本分支从 `main` 的 v3.5.2 切出，**只改底栏（dock）这一处**的材质与交互，
> 页面其余部分仍走 Material 3 Expressive，画风不作改动。
> 结论未定之前不合入 `main`；正式版本仍以 `main` 为准。

## 为什么单独开分支

底栏要做成「极致液态玻璃」，而项目的其余界面是 M3 Expressive —— 两者放在同一条发布线上
会互相牵扯：一处调参就要重新出一版。所以把这块单独摘出来，改到满意再决定要不要并回去。

应用内已有三档材质（`html[data-glass-material]`：`solid` / `translucent` / `glass`），
以及低性能降级（`html[data-perf='low']` 直接不挂滤镜），本分支不改变这套开关。

## 这一版改了什么

针对六条真机反馈，逐条对应：

### 一、观感

| # | 反馈 | 改法 |
| --- | --- | --- |
| 1 | 滑动时闪烁 | ① 底栏原本叠了**三层** `backdrop-filter`（本体透镜 / 折射层 blur(6px) / 散射层 blur(8px)），每层各自采样背景，逐帧重采样相位对不齐就闪 —— 去掉折射层那一层；② 色块位移**取整到整像素**（`--pill-x` 由 `toFixed(1)` 改 `Math.round`），消除半像素采样的抖动 |
| 2 | 上下色散太多太突兀 | 不做三通道位移（那是彩边与闪烁的共同来源），改成选中胶囊**上缘偏冷、下缘偏暖各 1px** 的极窄描边 —— 只留边缘那一丝分离感，纯合成层零采样成本 |
| 3 | 边缘扭曲区域太大 | 不再靠"调小强度"收敛（那只是变淡，分布照样铺满整块），改**衰减形状**：`lens.ts` 新增 `falloff` 参数，底栏取 **3**（三次方，原为平方），配合 `bezel 0.46 → 0.30`、`strength 1.0 → 0.9`、`zoom → 0.012`、backdrop 位移封顶 `10px → 7px` |

### 二、交互

| # | 反馈 | 根因与改法 |
| --- | --- | --- |
| 1 | 选中框滑走后原图标变白 | `schedule.css` 的 `.m3e-dock-tab.hovered` 用的是 `color-mix(on-surface 72%, on-surface-variant)`。深色主题下 `on-surface` 几乎是纯白，72% 权重就是"变白"——**注释里写着"不要用 on-surface"，代码却照做**。把权重翻过来：以 `on-surface-variant` 为主（82%），只掺一点 `on-surface` |
| 2 | 拖动没有跟手感 | 弹簧种子原本取**手指位置**，按下那一帧色块就被拽到指尖了。改取**色块当前所在格的中心**，从原处起跑去追手指 —— 滞后与回弹才有了来源 |
| 3 | 点按是闪现 | 根因：`pointerdown` 就直接进拖动态，而拖动态 CSS 是 `transition: none; transform: translate3d(var(--pill-x))`，于是轻点也让色块瞬移到指尖，`.m3e-dock-slider` 上那条带 overshoot 的弹簧过渡被整个跳过。改法：新增 **6px 拖动阈值**（`DRAG_SLOP`），轻点根本不进拖动态，只切标签，让 CSS 弹簧过渡去演"从旧位置弹到新位置"；真拖动才切到手写弹簧逐帧跟手 |

过冲量天然随跨距等比放大（同一条 `cubic-bezier(0.34, 1.56, 0.64, 1)`），所以"跨得越远弹得越明显"不需要额外参数。

## 怎么验

```bash
npm run dev -- --port 5173 --strictPort
APP_URL=http://127.0.0.1:5173/ node build/check-dock-tap.cjs   # 点按是不是真动画
APP_URL=http://127.0.0.1:5173/ node build/check-dock.cjs       # 跟手 / 配色
```

`build/check-dock-tap.cjs` 逐帧采样色块左边缘，断言三件事：轻点后有位移、
**存在中间帧**（闪现的话第一帧就到底）、**末段越过终点再回来**（= 过冲）。
只断言"最终到了新位置"是不够的 —— 闪现同样满足那一条。

两个方向都实跑对照过：**旧代码 2 通过 / 2 失败**（中间帧 0 帧、无过冲），
**新代码 4 通过 / 0 失败**。

> 检查本身也踩过一次假通过：第一版把 `pointerdown` 与 `pointerup` 连在同一 tick 派发，
> React 把状态更新批处理掉，`.dragging` 类从未落到 DOM 上，旧代码那条瞬移路径没被触发，
> 于是新旧都"通过"。现在按住 110ms，复现真实轻点时长。

## 未验证项

闪烁、色散、扭曲属于**观感**，本轮只做了改法与静态检查（构建、守卫、既有 dock 测试），
**没有在真机上对比过**。真机核验时请先关掉开发者选项的「指针位置」「显示布局边界」。
